 •   Nested Vectored Interrupt Controller
     •   is a ‘core peripheral’, closely coupled to the processor core
     •   handles Exceptions and Interrupts with low latency
     •   contains control logic and control registers for interrupt processing

CORTEX-M4 INTERRUPT SYSTEM
                       Cortex-M4 interrupts are classified into 2 groups
•   System Exception (“Exception”)                •   External Interrupt (“Interrupt”)
    •   15 for all Cortex M4 based chips              •   Up to 240, depending on the SoC
    •   Reset, NMI, Hard fault, Bus fault, etc.       •   Generally generated by / taken in through on-
    •   Generally generated within Cortex M4              chip peripherals
    •   E.g. Systick                                  •   E.g. Push-button
•   Every exception and external interrupt has an exception number (note: starts with
    1), which is fixed for the interrupt/exception : 1-15 for system exceptions, 16
    onwards for external interrupts
•   A related number is IRQn, which is nothing but <exception_number> - 16 defined
    in stm32l4s5xx.h (Drivers>CMSIS>Device>ST>STM32L4xx>Include) and is used
    by NVIC driver functions which can be found in core_cm4.h
•   (Drivers>CMSIS>Include)                                                                                                                     5

    •   IRQn is <0 for system exceptions and >=0 for external interrupts

VECTOR TABLE
 •   When an exc./int. takes place and is being handled by CPU, the CPU needs to locate the
     starting address of exc./int. handler
 •   Vector table is a part of memory used to store the starting addresses of the
 •   various exception/interrupt handlers
 •   Vector address is arranged according to exc./int. number x 4
 •   Processor reads this table and loads the starting address of handler into PC
 •   Vector table is nothing but an array of function pointers pointing to interrupt handlers, with
     the exception number used as the array index

VECTOR TABLE
 •   Vector table can be found in startup_stm32l4s5vitx.s (Core>Startup)
     •   The file also provides weak (meant to be overridden by the user) aliases for each
         exception handler to the Default_Handler
     •   The actual handlers can be found in stm32l4xx_it.h (Core>Inc)
 •   By default, vector table starts at memory address 0. Vector table can be
     relocated to another memory location by setting Vector Table Offset
     Register (VTOR) in SCB
