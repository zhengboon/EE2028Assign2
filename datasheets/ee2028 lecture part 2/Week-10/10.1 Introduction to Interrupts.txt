POLLING VS INTERRUPT

• Imagine processor is like a CEO working in his office, and devices are
  guests
   • Polling is like the CEO who goes to open the door periodically to see if a guest is there
   • Interrupt is like when a guest comes, he/she knocks on the door. CEO then stops
     what he/she is doing and prepares to welcome the guest

POLLING VS INTERRUPT

•   Alternative 1: Polling
    •   Periodically processor checks each device to see if it has a request
        • Takes CPU time even if no request is pending
        • How does software know when to let the system poll?


•   Alternative 2: Interrupts
    •   Give each device a wire (interrupt line) that it can use to signal the processor
        • When interrupt signalled, processor executes a routine called an interrupt service routine
          (ISR) to deal with the interrupt
        • No overhead when no requests pending

POLLING VS INTERRUPT

•   Polling
    •   (+) CPU determines how often it needs to poll. Potentially simpler software
    •   (-) CPU needs to check the device many times, and in most cases, the device might
        not have new data / situation which require attention from CPU
    •   (-) Most I/O devices operate at a much slower speed than CPU


•   Interrupt
    •   (+) More efficient since CPU can do other work
    •   (-) Harder to design, debug and test
    •   (-) Overhead/latency : CPU has to stop working, determine which device is
        requesting service, save its work before serving the request
