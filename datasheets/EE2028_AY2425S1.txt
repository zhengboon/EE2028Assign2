                                                                                                                 Q1. No.                                                                                   Memory Organization (For 32-bit ARM)
                                                                                                                   - Information is stored in the form of 0s and 1s. (When using higher-level languages,
                                                                                                                     the compiler translates source code into machine code that a computer's processor
                                                                                                                     can execute.)+9
                                                                                                                   - Memory: bit/ byte/ word (byte is the smallest addressable unit)
                                                                                                                   - A word may store:
                                                                                                                        ○ (part of) an instruction
                                                                                                                        ○ Data (float, string, integer, long, …)
                                                                                                                   - Any binary pattern can be interpreted as an instruction or as a number

                                                                                                                 Q2.
                                                                                                                   - Instruction ADD R4, R2, R3 is stored in memory -> can be located with an address
                                                                                                                   - Assume this address is 0x2000 31FC, the steps for executing the instruction are:




                                                                                                                  1. Program Counter (PC) should contain the address before executing this instruction:
                                                                                                                       0x2000 31FC
                                                                                                                  2. Control Unit (CU) sends address in PC to Processor-memory interface, issue Read
                                                                                                                     command.
                                                                                                                  3. CU loads the instruction into the Instruction Register (IR), now IR contains the
                                                                                                                     instruction in the forms of machine code (0s and 1s).
                                                                                                                  4. CU decodes the machine code, to determine the operation
                                                                                                                  5. CU sends the content of R2 and R3 and issues ADD command to Arithmetic & Logic
                                                                                                                     Unit (ALU)
                                                                                                                  6. CU gets the output from ALU and sends it to R4.
                                                                                                                  7. PC ++, pointing to the next instruction in the memory address:
                                                                                                                       0x2000 3200

                                                                                                                     operands.

                                                                                                                     of them may be a constant given explicitly in the instruction word, as #immediate.
                                                                                                                   - In this case, A and B are both memory locations.

                                                                                                                                                                                            ○ 1st pass: reversed = 0000 | 0001 = 0001
                                                                                                                                                                                            ○ 2nd pass: reversed = 0010 | 0000 = 0010

                                                                                                                                                                                       - Shift x to the right by 1 bit for the next round.
                                                                                                                                                                                            ○ 1st pass: x = 0101 >> 1 = 0010
                                                                                                                                                                                            ○ 2nd pass: x = 0010 >> 1 = 0001

              Interesting question asked:
              void altitude_read(char*)
              …
              char altitude_val[2]

              Why char* ?

              From the implementation you can see that we are expecting a pointer to the data, which is
              in form of 2 bytes. We thus need to make sure we reserved enough space.

                - In C, a byte buffer is traditionally char* because char is the basic character type
                  and is guaranteed to be size 1 byte (or 8 bits). Many legacy I²C/SPI APIs were written
                  this way.
                     ○ In that case, why don't we use uint_8?
                - Corner case: on very odd devices where a “byte” isn’t 8 bits, uint8_t may not exist,
                  but char always does.
                - Core reason:
                  In C’s strict-aliasing model, accessing the same memory through pointers of different,
                  incompatible types can be undefined behaviour (UB) #: the compiler may assume
                  they don’t overlap and optimize in ways that break your program.
                  Character types are a special exception: the standard allows any object’s bytes to be
                  accessed via char*, signed char*, or unsigned char*.
                  Therefore, using a char* as the buffer type for raw sensor data is safe and cannot
                  cause aliasing UB.
                  It’s ideal for I²C/SPI reads where we treat values as raw bytes first, and only later
                  reinterpret/assemble them into larger integers.

                   #
                    UB means the C standard imposes no requirements on the result—code may seem to
                   work, fail intermittently, or change with compiler flags/optimizations.

                                                           On page 15, under section 5.1.1.:




                                                           | 0x80 is equivalent to | 0b1000 0000, it sets the MSB of the sub -address to '1', and enables auto-

              Q6. Worst-Case Execution Time
                 - We assume ‘duration’ refers to the actual time spent by the processor in executing the ISR and not including the time
                   the ISR is in a preempted state because of a higher priority handler (though the duration for which the interrupt is
                   considered ‘active’ includes this time).
                 - Simple answer to that is: No.
                 - Depending on the exact condition within the device/peripheral that caused the interrupt to be raised, the time taken to
                   deal with it could vary.
                     ○ There could even be multiple conditions that needs to be dealt with simultaneously.
                     ○ There could also be data-dependent if-else scenarios.
                     ○ There is also a possibility that there are loops with variable number of iterations (for example, the number of new
                         data points to be read from a device buffer).
                 - All these could add to the uncertainty in the execution duration. However, in almost all practical designs, we calculate a
                   certain worst-case execution time (WCET), which is an upper bound on the execution duration. We should endeavour to
                   keep the WCET as low as possible by avoiding any heavy-duty processing of data within the handler. Any kind of wait
                   (so-called blocking code), such as delays() or waiting for a certain condition/even should also be avoided.

              Q7. Interrupt Configuration through Registers
              Interrupt Configuration Registers:
                 - ISER (Set Enable) & ICER (Clear Enable)
                     ○ To enable or disable an interrupt. "Disabled" as in NVIC is not set to watch out for a specific interrupt, it does not
                         mean the peripheral is disabled from generating an interrupt signal. (See Q4, Interrupt #2, during Period A)
                 - ISPR (Set Pending) & ICPR (Clear Pending)
                     ○ To set pending or clear pending state.
                     ○ If a specific interrupt is already pending, write a "1" to the corresponding ISPR bit has no effect (See Q4, Interrupt #
                         2, during Period A)
                     ○ If a specific interrupt handler is currently executing, write a "1" to the corresponding ICPR does not stop it.

                 - IPR (Priority)
                     ○ Each 8 bits are used to set the preempt and sub-priority of an interrupt.

                 - NVIC_IABR (Active Bit)
                     ○ Read the corresponding bit to determine if the specific interrupt is currently active
                     ○ You should understand "currently active" as: handler has started executing, but not done yet.
                     ○ Active does not necessarily mean the interrupt handler is executing. It might be preempted by another interrupt
                        with higher preempt. (See Q5, Interrupt #2 active state is set while the handler is interrupted by interrupt #1)
                 - System Exceptions Registers
                     ○ SHPRs (System Handler Priority)
                     ○ ICSR (Interrupt control and state), used for non-error type system exceptions, set/clear pending states, determine
                        the current executing exception number.
                     ○ HCSR (System handler control and state), used for error/fault type system exceptions. Enable/disable, determine
                        active state.
                 - Exception-masking Registers
                     ○ "Mask" as in "disguise" or "ignore"
                     ○ These registers can be used if you wish to ignore selective interrupts based on their priority.

                                                                     Q2. Asynchronous vs Synchronous Protocols
                                                                       - UART is an asynchronous communication mechanism. While the transmitter and receiver have identical settings
                                                                         concerning how long a bit period is, the receiver does not know when exactly this bit period starts since there
                                                                         is no shared clock.

                                                                       - Hence, the high-to-low transition of the RX signal at the beginning of the START bit is the only way for the
                                                                         receiver to know "that was the beginning of the bit period".

                                                                       - To guarantee that the START bit causes a transition, the STOP bit should be of the opposite logic level, and the
                                                                         default level of the RX (i.e., when idle) should also be the same logic level as STOP.
                                                                           ○ If the STOP bit is the same logic level as START (LOW), the transition is not guaranteed when two
                                                                              characters are transmitted back-to-back.




                                                                           ○ If the default level is not the same logic level as STOP (STOP HIGH, idle LOW), a time gap between the two
                                                                             characters will cause the beginning of the START bit to be indistinguishable.
